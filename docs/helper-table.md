# Basie helper table

This is the runtime's published helper table for the `CPM22` runtime (object
format §10). It lists every helper and service a compiled program may call:
its ordinal, its blob, how it is called, the helper-table version that
introduced it, its size, and its two stack figures.

- **Stack** is the most stack a call that returns can use, counting the
  2-byte return address of the `CALL`. The compiler adds it into a routine's
  `need(R)` ([memory safety](memory-safety.md) §7;
  [code generation](code-generation.md) §7).
- **Ending stack** is the most stack any path can use, counting a path that
  ends the program through a trap or `EXIT`. Such a path runs within the
  profile's guard band (64 bytes in `CPM22`), and a test checks that every
  ending figure, less its stack figure, fits the guard band.

The figures are not written by hand. `tools/stack.ts` follows every path
through each blob's code, including the blobs it calls, and finds the deepest
point. A blob the analysis can't follow states its figure on its `@blob` line
with `stack=N` (only `RETN`, which resets the stack pointer from `IX`); an
indirect jump names where it goes with `indirect=` (`EXIT` to the file
services' end-of-run hook, `CON_OUT` to the BIOS). BDOS calls count only their
return address, because CP/M 2.2's BDOS switches to its own stack. BIOS calls
run on the program's stack, so the guard band covers them.

The CP/M harness checks the analysis. Every conformance program runs with a
stack probe on each runtime blob it calls, and a test requires each measured
figure to be no larger than the computed one.

`deno task helpers` regenerates this table and the module the compiler
carries, `ref/compile/helper-table.ts`, from the runtime source. A test fails
if either is out of date. The interface keys are the CRCs described in object
format §10. The compiler writes its key into every program header, and the
linker refuses a library whose key for that version differs.
