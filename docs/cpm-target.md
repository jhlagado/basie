# Baton CP/M target 1.0

- Status: draft specification, not yet reviewed
- Date: 2026-10-03
- Related: [object format](object-format.md), [linker](linker.md),
  [toolchain](toolchain.md)

## 1. Scope

This document defines how a linked Baton program runs under CP/M 2.2 and CP/M 3
on a Z80 with 64K of RAM: the target profiles, the memory a program may use,
what the runtime library's `startup` blob does, and how a program exits. The
`startup` blob and every other environment-dependent routine come from the
blob library for the profile; nothing in this document is generated by the
compiler.

## 2. Profiles

Two profiles cover CP/M. Each is a blob library whose profile block
([object format](object-format.md), Section 7.2) holds the values below.

| Field | `CPM22` | `CPM3` |
| --- | --- | --- |
| Target class | 1 (CP/M 2.2) | 2 (CP/M 3) |
| Output kinds | `.COM` | `.COM` |
| Image base | `$0100` | `$0100` |
| Image limit | `$DC00`, the CCP base of a typical 62K system | `$E000`, a typical top of memory for a banked system |
| Nominal top | `$E406` | `$E000` |
| Default stack reserve | 512 bytes | 512 bytes |
| Option support | keep-CCP, re-runnable | re-runnable |
| Free restart vectors | none by default | none by default |
| Debugger margin | 5,120 bytes | 5,120 bytes |

The image limit and nominal top are typical values. A user with a different
system may build a profile variant with different values; the runtime code is
the same. Startup always checks the real machine (Section 4).

## 3. Memory

### 3.1 Map

```text
$0000  page zero (CP/M)
$0100  START   startup blob
       TEXT    code, read-only data, and data unless re-runnable
       DATA    initialised data, when re-runnable
       COPY    initial copy of DATA, when re-runnable
       --- end of stored image ---
       BSS     zero-initialised data, not stored
       FREE    free memory, available to the program at run time
       ...     stack, growing down
top    lowest resident system component (word at $0006)
```

### 3.2 The top of memory

The word at `$0006` holds the address of the lowest resident system component,
which is not always the BDOS:

- under CP/M 2.2 alone, the BDOS entry, six bytes above the BDOS base (the
  first six bytes hold the serial number);
- under `DDT`, `SID` or `ZSID`, the debugger, about 5K lower; and
- under CP/M 3, the resident BDOS or the lowest resident system extension
  (RSX).

In every case it is the correct top of memory for a program. The stack starts
there. Under CP/M 2.2 the first push lands on serial-number bytes, which nothing
checks after boot.

Typical transient program areas range from about 44K, on CP/M 2.2 systems with
large BIOSes or Z-System environments in high memory, to about 60K on banked
CP/M 3.

### 3.3 Page zero

The program must not treat any of page zero as free. CP/M 2.2 uses `$0000` to
`$0007` (the warm-boot jump, IOBYTE, current drive and BDOS jump), the default
file control blocks at `$005C` and `$006C`, and the default DMA buffer at
`$0080`. CP/M 3 also uses `$0050` (the drive the program was loaded from) and
`$0051` to `$0056` (password pointers and lengths). `$0040` to `$004F` is
conventionally BIOS scratch.

## 4. Startup

The `startup` blob is placed at `$0100`. It does this, in order:

1. **Set the DMA address** to a runtime buffer with BDOS function 26, before any
   other BDOS call. The command tail at `$0080` is overwritten only by BDOS
   calls that transfer data through the default DMA address. Moving the DMA
   address first keeps the command tail and the default FCBs intact for the
   whole run, with no copy.
2. **Read the top of memory** from `$0006`. With keep-CCP, subtract the CCP's
   size (2K) to get the usable top.
3. **Check memory.** If the usable top is below `REQUIRED`, print a message
   with BDOS function 9 and return to the CCP with `RET`. The CCP's stack is
   still in use at this point. It has seven free levels, enough for one BDOS
   call, which switches to the BDOS's own stack.
4. **Save the entry stack pointer**, with keep-CCP only.
5. **Set the stack pointer** to the usable top.
6. **Zero `BSS`.** Memory beyond the file holds whatever the previous program
   left.
7. **Copy `COPY` over `DATA`**, when re-runnable.
8. **Call `main`** through `MAIN`.
9. **Exit** (Section 5).

The first byte of the image must not be `$C9` (`RET`). CP/M 3's loader treats a
`.COM` file whose first byte is `$C9` as carrying a 256-byte RSX header.

A program too large for the real machine never reaches startup. The CP/M 2.2
CCP loads the file record by record and stops with `BAD LOAD` if the next
record would overwrite the CCP itself, so no Baton message appears. A 62K
system with the CCP at `$DC00` can load at most 56,064 bytes.

## 5. Exit

**Default: warm boot.** Startup gives the program the CCP's memory and exits
with `RST 0`, the one-byte form of `JP $0000`. Under CP/M 2.2 a warm boot
reloads the CCP and BDOS from the system tracks, about 5.5K, which takes
roughly 1 to 3 seconds on floppies; under CP/M 3 and on most hard-disk systems
it is fast. A warm boot also resets the DMA address and the disk login.

**Keep-CCP option (CP/M 2.2).** Startup saves the entry stack pointer, places
the program's stack below the CCP, and returns to the CCP through the saved
pointer. This costs about 2K of memory and avoids the warm boot.

**Return codes (CP/M 3).** On exit, the runtime sets the program return code
with BDOS function 108: success when `main` returns normally, failure for an
unhandled error or a trap. `SUBMIT` and conditional command lines can test it.
CP/M 2.2 has no return codes.

## 6. Command line

The command tail is at `$0080`: a length byte followed by the text. The default
FCB at `$005C` is 36 bytes long, running to `$007F`, and the second default FCB
at `$006C` overlaps bytes 16 to 35 of the first. The CP/M 2.2 CCP converts the
whole command line to upper case, so Baton's argument interface cannot promise
to preserve case.

## 7. Re-running without reloading

Z-System's `GO` command and similar facilities re-enter a program at `$0100`
without reloading it. `BSS` is correct on re-entry, because startup clears it.
Initialised data is not: it keeps the values the previous run left.

The **re-runnable** option, off by default, fixes this. The linker stores a copy
of the initial data in the `COPY` section, and startup restores it before
calling `main`. It costs the size of the initialised data a second time, plus a
short copy loop.

Without the option, a program must be reloaded from disk to run again. The
documentation says so, and says not to re-enter it with `GO`.

## 8. Restart vectors and interrupts

Other users of low memory:

- `DDT`, `SID` and `ZSID` use `RST 38h` for breakpoints;
- BIOSes running in interrupt mode 1, including Amstrad's CP/M and many
  home-built systems, use `RST 38h` as their interrupt entry; and
- the non-maskable interrupt vector at `$0066` falls inside the first default
  FCB, which matters only on hardware that generates NMIs.

A compact calling convention through `RST` would save two bytes per call to a
common helper. On CP/M it is safe only for vectors the profile declares free,
and never for `RST 38h`. Both CP/M profiles declare none free by default.
Where a profile variant declares some, startup installs them, and the library
marks each installed helper as a root.

A Baton program does not change the interrupt mode or the `I` register, and
installs nothing at `$0038`.

## 9. Other CP/M environments

- **CP/M 3 (banked).** The transient program area can reach about 60K, the CCP
  is not resident during the run, and the top of memory is the resident BDOS or
  lowest RSX. The `CPM3` profile applies.
- **Z-System (ZCPR3).** The environment descriptor and resident command and
  flow-control packages in high memory reduce the transient program area by
  about 2K to 8K. The word at `$0006` still gives the correct top. `GO`
  re-entry is covered by Section 7.

## 10. Traps

The library provides one reporter blob per trap reason. A trap site is a call
to its reporter, as design decision D11 in the
[design decisions](design-decisions.md) describes. The
reporter prints, through BDOS function 9 or console output:

```text
TRAP bounds at 1A3F
```

then sets the CP/M 3 return code to failure and exits as in Section 5. The
address is that of the call instruction at the trap site. The trap lookup mode
of the Baton executable turns it into a source position (see the
[toolchain](toolchain.md)).
