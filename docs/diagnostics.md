# Basie diagnostic codes

- Status: working register; grows with the reference compiler
- Related: [design decisions](design-decisions.md) D39 (message file),
  [roadmap](roadmap.md) step 48, [conformance tests](../tests/conformance/README.md)

Every diagnostic of the compiler and the linker has a stable kebab-case
**code**, used by the conformance tests (`// expect error: CODE at
LINE:COLUMN`), and a stable **number**, which is what `BASIE.COM` and
`BLINK.COM` carry; the text lives in `BASIE.MSG` (design decision D39,
[toolchain](toolchain.md) §7.3). The position is the first byte of the
construct the diagnostic names. Codes and numbers are never reused for a
different meaning, and numbers are append-only within their ranges:

| Numbers | Range |
| --- | --- |
| 1–19 | Lexical |
| 20–39 | Structure and names |
| 40–69 | Declarations and types |
| 70–99 | Expressions and statements |
| 100–129 | Ownership and routines |
| 190–199 | Capacity and internal |
| 200–239 | Linker |

`^1` and `^2` in a message are replaced by arguments: a name, a number or a
type. The tables below are generated from `ref/compile/messages.ts` by
`deno task msg`, which also writes `BASIE.MSG`; a test fails if they drift.
