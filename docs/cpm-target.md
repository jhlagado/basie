## 1. Scope

This document defines how a linked Basie program runs under CP/M 2.2 and CP/M 3
on a Z80 with 64K of RAM: the target profiles, the memory a program uses, what
the runtime library's `startup` blob does, how a program exits, and how traps
are reported. All of this code comes from the blob library for the profile;
none of it is generated by the compiler.

## 2. Profiles

Two profiles cover CP/M. Each is a blob library whose profile block
([object format](object-format.md), Section 7.2) holds these values:

| Field | `CPM22` | `CPM3` |
| --- | --- | --- |
| Target class | 1 (CP/M 2.2) | 2 (CP/M 3) |
| Output kinds | `.COM` | `.COM` |
| Image base | `$0100` | `$0100` |
| Image limit | `$DC00`, the CCP base of a typical 62K system | `$E000`, a typical top of memory for a banked system |
| Nominal top | `$E406` | `$E000` |
| CCP size | `$0800` | 0 |
| Guard band | 64 bytes | 64 bytes |
| Option support | keep-CCP, re-runnable | re-runnable |
| Free restart vectors | none | none |
| Debugger margin | 8,192 bytes | 8,192 bytes |

The image limit and nominal top are typical values. A user with a different
system can build a profile variant with other values from the same runtime
code. Startup always checks the real machine (Section 4).

The debugger margin covers `SID`, which takes about 8K; `DDT` takes about 5K.

## 3. Memory

### 3.1 Map

```text
$0000  page zero (CP/M)
$0100  START   startup blob
       TEXT    code, read-only data, and data unless re-runnable
       DATA    initialised data, when re-runnable
       COPY    initial copy of DATA, when re-runnable
       --- end of stored image ---
       BSS     zero-initialised data, not stored
       FREE    free memory, available to the program at run time
       ...     stack, growing down
top    usable top of memory (Section 3.2)
```

### 3.2 The top of memory

The word at `$0006` is the address of the lowest resident system component,
not always the BDOS:

- under CP/M 2.2 alone, the BDOS entry, six bytes above the BDOS base, whose
  first six bytes hold the serial number;
- under `DDT`, `SID` or `ZSID`, the debugger; and
- under CP/M 3, the resident BDOS or the lowest resident system extension.

The **usable top** is:

- by default, the word at `$0006`; and
- with keep-CCP, the word at `$0006` minus 6 minus the profile's CCP size,
  which is the CCP base: `$E406 − 6 − $0800 = $DC00` on a typical 62K system.

By default the stack starts at the word at `$0006`. Under CP/M 2.2 its first
pushes overwrite the BDOS serial number; this is harmless because the program
exits with a warm boot, which reloads the BDOS from disk.

Typical transient program areas range from about 44K, on CP/M 2.2 systems with
large BIOSes or Z-System environments in high memory, to about 60K on banked
CP/M 3.

### 3.3 Page zero

No part of page zero is free. CP/M 2.2 uses `$0000` to `$0007` (the warm-boot
jump, IOBYTE, current drive and BDOS jump), the default file control blocks at
`$005C` and `$006C`, and the default DMA buffer at `$0080`. CP/M 3 also uses
`$0050` (the drive the program was loaded from) and `$0051` to `$0056`
(password pointers and lengths). `$0040` to `$004F` is conventionally BIOS
scratch.

## 4. Startup

The `startup` blob is placed at `$0100` and reads the link-time options from
the `OPTIONS` pseudo-object. It does this, in order:

1. **Set the DMA address** to a runtime buffer with BDOS function 26. The
   command tail at `$0080` is overwritten only by BDOS calls that transfer data
   through the default DMA address; moving it before the first such call keeps
   the command tail and default FCBs intact for the whole run, with no copy.
2. **Compute the usable top** (Section 3.2).
3. **Check memory.** If the usable top is below `REQUIRED`, print a message with
   BDOS function 9, set the CP/M 3 return code to `$FF03`, and return to the CCP
   with `RET`. The CCP's stack is still in use. It has seven free levels, enough
   for one BDOS call, since the BDOS switches to its own stack.
4. **Save the entry stack pointer,** with keep-CCP only.
5. **Set the stack pointer** to the usable top.
6. **Zero `BSS`,** unless its size is 0. Memory beyond the file holds whatever
   the previous program left.
7. **Copy `DATACOPY` over `DATA`,** when re-runnable and the size is not 0.
8. **Call `main`** through `MAIN`.
9. **Exit** (Section 5).

Steps 6 and 7 test for size 0 before any `LDIR`, because `LDIR` with `BC = 0`
moves 65,536 bytes.

The first byte of the image must not be `$C9` (`RET`); CP/M 3's loader treats a
`.COM` file beginning with `$C9` as carrying a 256-byte RSX header. A startup
blob that begins with `LD C,26` satisfies this; the conformance suite checks
it.

### 4.1 Stack checking

The compiler computes, for every routine, the most stack its call subtree can
use outside cycles, `need(R)`, and writes `need(main)` plus the profile's guard
band into the `LIMITS` record as the stack reserve
([memory safety](memory-safety.md), Section 7). `REQUIRED` is therefore a true
bound for everything reachable from `main` outside cycles, and startup's memory
check (step 3) guarantees that part can never overflow. The `STACK=` option can
only raise it.

Every cycle of calls passes through a forward-declared routine, because a
routine that calls itself must be forward-declared. Each **forward-declared**
routine begins with the **activation-capacity check**, which raises the
`activation-capacity` trap: a call to the runtime's
stack-check helper with `need(R)`, which traps if the stack pointer minus
`need(R)` minus the guard band would fall below `FREE`. No other routine needs
a check.

The guard band is a profile value. It covers the trap reporter's call into the
BDOS, which switches to its own stack after a few pushes, and an
interrupt-mode-1 BIOS pushing onto the program's stack. Runtime helpers' own
stack use is counted in `need(R)` from figures published in the helper table.
The helper follows the reporter contract (Section 10.2), so the trap reports
the routine's prologue, which the line table maps to the routine's header.

### 4.2 Programs too large to load

A program too large for the real machine never reaches startup. The CP/M 2.2
CCP loads the file record by record and stops with `BAD LOAD` if the next record
would reach its own base, so no Basie message appears. A 62K system with the CCP
at `$DC00` can load at most about 56,064 bytes; the exact figure depends on the
CCP's comparison and may be 128 bytes less.

## 5. Exit

**Return codes (CP/M 3).** Before exiting, the runtime sets the program return
code with BDOS function 108:

| Code | Meaning |
| --- | --- |
| `$0000` | `main` returned normally |
| `$FF01` | `main` returned an unhandled failure |
| `$FF02` | A trap |
| `$FF03` | Not enough memory to start |

Values from `$FF00` count as failure to the CP/M 3 CCP's `:` conditional. CP/M
2.2 has no return codes.

**Default: warm boot.** The program exits with `RST 0`, the one-byte form of
`JP $0000`. Under CP/M 2.2 a warm boot reloads the CCP and BDOS from the system
tracks, about 5.5K, which takes roughly 1 to 3 seconds on floppies; under CP/M 3
and on most hard-disk systems it is fast. A warm boot also resets the DMA
address and the disk login.

**Keep-CCP (CP/M 2.2).** The program's stack starts below the CCP, and exit
restores the saved entry stack pointer and returns to the CCP. This costs about
2K of memory and avoids the warm boot.

## 6. Command line

The command tail is at `$0080`: a length byte followed by the text. The default
FCB at `$005C` is 36 bytes long, running to `$007F`, and the second default FCB
at `$006C` overlaps bytes 16 to 35 of the first. The CP/M 2.2 CCP converts the
whole command line to upper case, so Basie's argument interface cannot promise
to preserve case.

## 7. Re-running without reloading

Z-System's `GO` command and similar facilities re-enter a program at `$0100`
without reloading it. `BSS` is correct on re-entry, because startup clears it.
Initialised data is not: it keeps the values the previous run left.

The **re-runnable** option, off by default, fixes this. The linker stores a copy
of the initial data in `COPY`, and startup restores it before calling `main`.
This covers the runtime library's own `data` blobs as well as the program's. It
costs the size of the initialised data a second time, plus a short copy loop.

Without the option, a program must be reloaded from disk to run again. The
documentation says so, and says not to re-enter it with `GO`.

## 8. Restart vectors and interrupts

Other users of low memory:

- `DDT`, `SID` and `ZSID` use `RST 38h` for breakpoints;
- BIOSes running in interrupt mode 1, including Amstrad's CP/M and many
  home-built systems, use `RST 38h` as their interrupt entry;
- `RST 0` is the warm-boot jump; and
- the non-maskable interrupt vector at `$0066` falls inside the first default
  FCB, which matters only on hardware that generates NMIs.

A compact calling convention through `RST` would save two bytes per call to a
common helper. On CP/M it is safe only for vectors the profile declares free,
and never `RST 0` or `RST 38h`. Both CP/M profiles declare none free, and
Basie's own code never takes a vector for compression (design decision D46). A profile
variant that declares some has startup install them, and its library marks each
installed helper as a root.

A Basie program does not change the interrupt mode or the `I` register, and
installs nothing at `$0038`.

## 9. Other CP/M environments

Every runtime call to CP/M goes through one routine that saves `IX` and `IY`
around `CALL 5`, and the BIOS console call saves them too. CP/M 2.2 doesn't
promise to preserve those registers, and a BIOS written in Z80 code may use
them. Compiled code keeps its frame pointer in `IX` and the runtime passes
`RETN`'s count in `IY`, so a clobbered register would be fatal. The minimal
test harness preserves every register, so this rule is checked by running
the example programs under real CP/M 2.2 on the Triptych machine, where the
BIOS does use them.

- **CP/M 3 (banked).** The transient program area can reach about 60K, the CCP
  is not resident while a program runs, and the top of memory is the resident
  BDOS or lowest system extension. The `CPM3` profile applies.
- **Z-System (ZCPR3).** The environment descriptor and resident command and
  flow-control packages in high memory reduce the transient program area by
  about 2K to 8K. The word at `$0006` still gives the correct top. `GO`
  re-entry is covered by Section 7.

## 10. Traps

### 10.1 Reporters

The library provides one reporter blob for each trap reason (`bounds`,
`narrowing`, `division-by-zero`, `loop-range`, `activation-capacity`,
`float-overflow`, `float-invalid`, `stale-handle`, `ownership-cycle`, `pool-full`, `assertion`). Each prints:

```text
TRAP bounds at 1A3F (BASIE name [T=1A3F])
```

then sets the return code to `$FF02` and exits as in Section 5. An unhandled failure from `main` prints `FAIL` and the code in decimal, such as `FAIL 48`, sets the return code to `$FF01`, and exits the same way. The address is
that of the instruction that called into the failing code: the trap site in the
program. The parenthesis is the command that looks the address up (Section
10.3, design decision D47); a program under CP/M 2.2 doesn't know the name it
was run by, so `name` stands for it.

### 10.2 Reporter contract

A reporter is entered with the **site's return address on top of the stack**,
and computes the site address as that return address minus 3. Two kinds of
code enter it:

- **Inline trap sites** in compiled code end with a 3-byte call to the
  reporter: either `CALL cc,reporter` (3 bytes in all, when the check leaves
  its result in a condition flag) or `JR cc,skip` followed by `CALL reporter`
  (5 bytes). In both cases the call instruction is the last 3 bytes of the site,
  so the return address minus 3 is the call.
- **Runtime helpers** that detect a failure, such as division by zero inside a
  division helper, **jump** to the reporter with `JP`, never `CALL`, after
  restoring the stack pointer to its value on entry to the helper. The top of
  the stack is then the return address pushed by the program's `CALL helper`,
  and that address minus 3 is the call to the helper, inside the statement that
  trapped.

A helper that cannot restore its entry stack pointer cheaply on a failure path
records the entry value when it starts, or doesn't trap itself and instead
returns a condition flag for an inline site to test. A reporter may destroy
every register, since it never returns.

Three further rules keep the reported site correct:

1. **No tail calls to helpers.** Compiled code enters a runtime helper only with
   a 3-byte `CALL`, never with a tail-call `JP`. (Program routines may still
   tail-call each other.) A helper reached by `JP` from compiled code would
   leave the caller's caller's return address on the stack, and the report
   would name the wrong routine.
2. **Helpers that call helpers.** A helper that needs another helper as a
   subroutine calls a non-trapping variant that returns a condition flag, and
   traps itself, with its own entry stack restored. A helper may also finish
   by jumping to another trapping helper, but only after restoring its own entry
   stack pointer, so the stack still holds the program's return address.
3. **`RST` helpers never trap.** A helper entered through a restart vector has
   a 1-byte call instruction, so "return address minus 3" would be wrong.

The conformance suite checks every library helper's failure path: the reporter
must be reached with the stack pointer equal to its value immediately after the
program's call.

### 10.3 Lookup

The `BASIE` executable's trap lookup mode turns the printed address into a
source position using the line table ([toolchain](toolchain.md), Section 8).
